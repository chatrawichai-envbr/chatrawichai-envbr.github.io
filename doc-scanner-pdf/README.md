# สแกนเอกสารเป็น PDF (Doc Scanner PDF)

เว็บแอปแปลงรูปภาพเอกสารหรือภาพถ่ายเอกสารจากกล้องเป็นไฟล์ PDF
เขียนด้วย **HTML + CSS + JavaScript ล้วน** (ไม่มี PHP / TypeScript / Python ไม่ต้อง build)
ภาพทั้งหมดประมวลผลในเบราว์เซอร์ของผู้ใช้ **ไม่มีการอัปโหลดไปที่เซิร์ฟเวอร์ใด**

**ใช้งานออนไลน์:** https://chatrawichai-tech.github.io/doc-scanner-pdf/

**เวอร์ชัน Google Apps Script:** [`chatrawichai-tech/claude4gas`](https://github.com/chatrawichai-tech/claude4gas)
(โฟลเดอร์ `doc-scanner-pdf-gas/`) — แปลงอัตโนมัติจากโค้ดชุดนี้ ติดตั้งเป็นเว็บแอปในบัญชี Google ของคุณเองได้

**แอป Android (มือถือและแท็บเล็ต):** [`chatrawichai-tech/claude4app`](https://github.com/chatrawichai-tech/claude4app)
(โฟลเดอร์ `doc-scanner-pdf-android/`) — แปลงอัตโนมัติจากโค้ดชุดนี้ ทำงานในเครื่องโดยไม่ต้องใช้อินเทอร์เน็ต
ดาวน์โหลดไฟล์ APK (รุ่นล่าสุด เซ็นด้วยกุญแจถาวร) ได้ที่ https://chatrawichai-tech.github.io/doc-scanner-pdf-android/

## ความสามารถ

| ฟังก์ชัน | รายละเอียด |
|---|---|
| นำเข้าภาพ | ถ่ายด้วยกล้องในแอป (ถ่ายต่อเนื่องหลายหน้า มีกรอบตรวจจับเอกสารแบบสด + ไฟแฟลช), เปิดกล้องของเครื่อง, เลือกหลายรูปจากคลังภาพ, ลากไฟล์มาวาง, วางจากคลิปบอร์ด (Ctrl+V) — รองรับ JPEG, PNG, WebP, **HEIC/HEIF** (รูปจาก iPhone และมือถือ Android หลายรุ่น — ถอดรหัสในเครื่องแม้เบราว์เซอร์จะเปิดเองไม่ได้), GIF, BMP, AVIF |
| ครอปตามขอบกระดาษ | ตรวจจับขอบกระดาษอัตโนมัติ แล้วดัดภาพที่ถ่ายเอียงให้ตรง (perspective correction) |
| ครอปอิสระ | ลากมุมทั้ง 4 หรือลากขอบได้อย่างอิสระ มีแว่นขยายช่วยวางมุมให้แม่น, ปุ่ม "เต็มภาพ", ใช้ปุ่มลูกศรบนคีย์บอร์ดได้ |
| ปรับแสง | แถบเลื่อนเพิ่ม/ลดความสว่าง และความคมชัด (คอนทราสต์) |
| ลบเงาดำ | ปรับพื้นกระดาษให้ขาวเรียบเท่ากันทั้งแผ่น ลบเงามือ/เงาโทรศัพท์ โดยคงสีโลโก้และรูปภาพในเอกสารไว้ |
| สีสดคมชัด | สีสันปกติแต่คมชัดขึ้น (ลบเงา + เพิ่มความอิ่มสี + เพิ่มความคม) |
| ขาวดำตัวอักษรคม | ขาว–ดำชัดเจน ตัวอักษรเข้มคม ปรับ "ความเข้มตัวอักษร" ได้ |
| แปลงภาพเป็นข้อความ (OCR) | อ่านข้อความภาษาไทย + อังกฤษ ทีละหน้าหรือทุกหน้า แก้ไขข้อความได้ แล้วคัดลอก / บันทึก .txt / แชร์ |
| PDF ค้นหาข้อความได้ | ฝังข้อความที่อ่านได้ (OCR) ไว้ใต้ภาพแบบมองไม่เห็น — ค้นหา เลือก คัดลอกข้อความใน PDF ได้ โดยหน้าตาภาพไม่เปลี่ยน |
| อื่น ๆ | โหมดต้นฉบับ/โทนเทา, หมุนภาพ, เรียงลำดับ/ลบหน้า, ใช้การตั้งค่ากับทุกหน้า |
| สร้าง PDF | ขนาด A4 / Letter / Legal / A5 / ตามขนาดภาพ, แนวตั้ง/นอนอัตโนมัติ, ขอบกระดาษ, เลือกคุณภาพ/ขนาดไฟล์, ดาวน์โหลดหรือแชร์ (มือถือ) |
| แปลง PDF เป็นรูป JPG | ทุกหน้าหรือเลือกหน้า (เช่น `1-3, 5`) ขนาด **Small** 96 dpi (ส่งทางแชต) / **Standard** 150 dpi / **High** 300 dpi — หน้าเดียวได้ `.jpg` หลายหน้ารวมเป็น `.zip` |
| แปลง PDF เป็น Word (.docx) | ข้อความภาษาไทยตรงตามต้นฉบับทุกตัวอักษร คงบรรทัด ย่อหน้า คอลัมน์ (แท็บ) หัวเรื่อง และการขึ้นหน้าใหม่ — หน้าที่เป็นภาพสแกนอ่านด้วย OCR และแจ้งให้ตรวจทาน, รองรับไฟล์ที่มีรหัสผ่าน |

## วิธีใช้งาน

1. เปิด https://chatrawichai-tech.github.io/doc-scanner-pdf/ หรือเปิดไฟล์ `index.html` ในเครื่องได้ทันที (ดับเบิลคลิก)
   ไลบรารีทั้งหมดอยู่ในโฟลเดอร์ `vendor/` จึงไม่ต้องพึ่ง CDN ภายนอก
2. กด **ถ่ายภาพ** หรือ **เลือกรูปภาพ** ระบบจะครอปตามขอบกระดาษ ลบเงา และปรับภาพให้อัตโนมัติ
3. แตะที่หน้าเพื่อ **ครอป / ปรับขอบ** หรือเปลี่ยนรูปแบบภาพ ปรับแสง หมุนภาพ
4. กด **สร้าง PDF** เลือกขนาดกระดาษ แล้วกด **ดาวน์โหลด PDF**
   (เปิด **ค้นหาข้อความได้ (OCR)** ถ้าต้องการค้นหา/คัดลอกข้อความใน PDF)
5. ต้องการข้อความ: กด **ข้อความ** ที่แถบล่าง (ทุกหน้า) หรือ **แปลงหน้านี้เป็นข้อความ (OCR)** ในหน้าแก้ไข
6. แปลงไฟล์ PDF: กด **แปลงไฟล์ PDF เป็นรูป JPG / Word** ที่หน้าแรก (หรือลากไฟล์ PDF มาวาง) เลือก **รูปภาพ JPG**
   หรือ **Word (.docx)** แล้วกดแปลง — ไฟล์ถูกบันทึกอัตโนมัติ และแชร์ได้บนมือถือ (เฉพาะชนิดไฟล์ที่ระบบแชร์ได้)

### แปลงไฟล์ PDF เป็นรูป JPG / Word

- อ่านไฟล์ PDF ด้วย PDF.js ในเครื่องทั้งหมด (ไม่ส่งไฟล์ไปที่ใด) โหลดตัวอ่านเฉพาะตอนเปิดไฟล์ PDF ครั้งแรก
  ไม่รันสคริปต์หรือฟอร์ม XFA ในไฟล์ จำกัดไฟล์ 200 MB, ภาพในไฟล์ 80 ล้านพิกเซล, รูป JPG ครั้งละ 200 หน้า, Word ครั้งละ 1,000 หน้า
- **JPG:** วาดแต่ละหน้าบนพื้นขาวตามความละเอียดที่เลือก — หน้าที่ใหญ่มาก (เช่น A0) ลดความละเอียดลงให้อยู่ใน 16 ล้านพิกเซล
  (เพดานของ Safari บน iPhone/iPad) และแจ้ง dpi ที่ได้จริง ชื่อไฟล์ตามไฟล์ PDF เช่น `รายงาน-01.jpg` ใน `รายงาน-jpg.zip`
- **Word — ภาษาไทยถูกต้อง:** ใช้ข้อความ Unicode ที่ฝังอยู่ในไฟล์ PDF โดยตรง (ไม่อ่านจากภาพ) จึงตรงตามต้นฉบับทุกตัวอักษร แล้วแก้ปัญหา
  ที่ทำให้คำไทยเพี้ยนเมื่อดึงข้อความจาก PDF:
  - วรรณยุกต์/สระที่ฟอนต์วาดด้วยรูปอักษรพิเศษซึ่งไม่มีรหัส Unicode (PDF จาก Chrome, Android, Word ฯลฯ) — อ่านข้อความแทน
    `/ActualText` จากไฟล์เอง (`js/pdf-actualtext.js`) ซึ่ง PDF.js ไม่ส่งออกมา ไม่งั้นคำอย่าง "ที่" จะกลายเป็น "ที"
  - อักขระ PUA ของฟอนต์ไทยรุ่นเก่า (U+F700–U+F71A), สระอำที่เก็บเป็น "ํ + า", ลำดับสระ/วรรณยุกต์ที่สลับกัน,
    อักขระที่มองไม่เห็น และฟอนต์รุ่นเก่าที่ใช้รหัส TIS-620 โดยไม่บอกว่าเป็นภาษาไทย (`js/thai-text.js`)
  - ตรวจทุกหน้า: ถ้ายังมีอักษรที่ไม่รู้รหัสเหลืออยู่ แจ้งเลขหน้าให้ตรวจทาน (เสียมากจะอ่านหน้านั้นด้วย OCR แทน)
- ไฟล์ Word ใช้ฟอนต์ TH Sarabun New 16 pt (เลือก Tahoma หรือ Leelawadee UI ได้) ตั้งภาษาไทยให้ Word ตัดคำ/ตรวจคำได้
  หัวเรื่องขนาดใหญ่กว่าเนื้อหาตามต้นฉบับ — ได้เฉพาะข้อความ (ไม่รวมรูปภาพ เส้นตาราง และการจัดหน้าแบบละเอียด)
- **หน้าที่เป็นภาพสแกน** ไม่มีข้อความในไฟล์ จึงอ่านด้วย OCR (ลบเงาและเส้นตารางก่อนอ่านเหมือนการแปลงภาพถ่าย) — OCR อ่านผิดได้
  หน้าต่างจะบอกเลขหน้าที่อ่านด้วย OCR ให้ตรวจทานทุกครั้ง; เลือก "ข้อความในไฟล์เท่านั้น" หรือ "OCR ทุกหน้า" ได้
- ต้องเปิดผ่านเว็บไซต์ (https) — เบราว์เซอร์ไม่โหลด PDF.js (ES module) เมื่อเปิดไฟล์ `index.html` จากเครื่องโดยตรง

### การแปลงภาพเป็นข้อความ (OCR)

- ใช้ Tesseract.js อ่านข้อความในเครื่องของผู้ใช้ทั้งหมด (ไม่ส่งภาพไปที่ใด) โหลดตัวอ่านเฉพาะตอนกดใช้งานครั้งแรก
  (ข้อมูลภาษาไทย + อังกฤษ ประมาณ 4 MB และตัวอ่านประมาณ 4 MB — ครั้งต่อไปใช้แคชของเบราว์เซอร์)
- ก่อนอ่าน ระบบครอปตามกรอบ ลบเงา แปลงเป็นโทนเทา และ **ลบเส้นตาราง** ให้อัตโนมัติ (เส้นตารางทำให้ OCR ข้ามข้อความในตาราง)
  — ในการทดสอบ ความแม่นยำเพิ่มจากประมาณ 60% เป็น 94–99% และคงการจัดคอลัมน์ของตารางไว้
- ปรับสระอำที่ OCR ให้ผลเป็น "ํา" ให้เป็น "ำ" ตัวเดียว เพื่อให้ค้นหา/คัดลอกได้ถูกต้อง
- เหมาะกับเอกสารพิมพ์ ลายมือเขียนจะอ่านได้ไม่ดี และควรตรวจทานข้อความทุกครั้ง (แก้ไขในช่องข้อความได้โดยตรง)
- ต้องเปิดผ่านเว็บไซต์ (เช่น GitHub Pages) — ไม่รองรับเมื่อเปิดไฟล์ `index.html` จากเครื่องโดยตรง

### PDF ที่ค้นหาข้อความได้ (Searchable PDF)

- เปิดสวิตช์ **ค้นหาข้อความได้ (OCR)** ในหน้าต่างสร้าง PDF แล้วเลือกภาษา (ระบบจำค่าที่เลือกไว้ครั้งต่อไป)
- แต่ละหน้าจะถูกอ่านข้อความ แล้ววางข้อความไว้ **ตรงตำแหน่งเดียวกับในภาพ** แบบมองไม่เห็น (PDF text render mode 3)
  ภาพที่แสดงเหมือนเดิมทุกพิกเซล แต่ค้นหาด้วย Ctrl+F, ลากเลือก และคัดลอกข้อความได้ในโปรแกรมอ่าน PDF ทั่วไป
- ตารางแยกข้อความตามคอลัมน์ให้ตรงตำแหน่ง, ปรับสระอำให้ค้นหาได้ถูกต้อง, ข้ามบรรทัดที่ความมั่นใจต่ำ (มักเป็นภาพ/โลโก้)
- ฝังฟอนต์ Sarabun เฉพาะตัวอักษรที่ใช้ (ไฟล์ใหญ่ขึ้นประมาณ 10–20 KB) และใช้ผล OCR ร่วมกับหน้าต่าง "แปลงภาพเป็นข้อความ"
  (หน้าที่อ่านแล้วไม่ต้องอ่านซ้ำ)
- ใช้เวลาเพิ่มหน้าละหลายวินาที กด **หยุด** ได้ระหว่างสร้าง — ถ้าอ่านข้อความไม่สำเร็จ ยังได้ไฟล์ PDF ตามปกติพร้อมคำเตือน

> **กล้องในแอป** ต้องเปิดผ่าน `https://` หรือ `http://localhost` และเบราว์เซอร์ต้องอนุญาตกล้องให้เว็บไซต์
> (เบราว์เซอร์ในแอป LINE/Facebook มักไม่อนุญาต) ถ้าใช้ไม่ได้ ปุ่ม **ถ่ายภาพ** จะเปิดกล้องของเครื่องแทน ซึ่งใช้ได้ทุกกรณี:
> - รู้ล่วงหน้าว่าใช้ไม่ได้ (http ธรรมดา, เบราว์เซอร์แจ้งว่าไม่อนุญาตกล้อง, ถูกฝังในกรอบที่ห้ามกล้อง) → เปิดกล้องของเครื่องทันที
> - ขอสิทธิ์แล้วไม่ได้ → หน้ากล้องบอกเหตุผล วิธีอนุญาต และปุ่ม **ใช้กล้องของเครื่อง** / **ลองอีกครั้ง**
>   จากนั้นจำไว้ 7 วัน (ครั้งต่อไปเปิดกล้องของเครื่องเลย) จนกว่าเบราว์เซอร์จะแจ้งว่าอนุญาตกล้องแล้ว

### นำขึ้นเว็บ (แนะนำ เพื่อใช้กล้องบนมือถือ)

เว็บไซต์เผยแพร่ผ่าน GitHub Pages ของ repo [`chatrawichai-tech/chatrawichai-tech.github.io`](https://github.com/chatrawichai-tech/chatrawichai-tech.github.io)
ในโฟลเดอร์ `doc-scanner-pdf/` (→ https://chatrawichai-tech.github.io/doc-scanner-pdf/) ส่วนโค้ดทั้งหมดอยู่ใน repo `claude4code` (เดิมชื่อ `claude`)
ทุกครั้งที่แก้ไข:
1. รันชุดทดสอบในเบราว์เซอร์ทั้งหมด (`tools/tests`) — ต้องผ่านก่อนเผยแพร่ (CI รันซ้ำทุกครั้งที่ push)
2. `tools/publish-site.sh` สร้างโฟลเดอร์เว็บจาก commit ที่ push แล้ว ประทับเลข commit (`tools/stamp-build.sh`)
   ลงในโฟลเดอร์ `doc-scanner-pdf/` ของ repo เว็บไซต์ แล้ว commit/push repo นั้น
3. CI ของ repo เว็บไซต์ตรวจเว็บจริงว่าให้บริการเวอร์ชันใหม่ครบทุกไฟล์ (`version.json`) และ CI ของ repo นี้ตรวจทุกวันว่าไม่มีการแก้ที่ยังไม่เผยแพร่

ลิงก์เดิม https://chatrawichai-tech.github.io/claude/ (ที่อยู่สมัย repo ยังชื่อ `claude`) พาไปยังที่อยู่ใหม่ให้อัตโนมัติ

รายการการเปลี่ยนแปลงแต่ละครั้งอยู่ใน `CHANGELOG.md` ของ repo

### อัปเดตเวอร์ชัน / ล้างแคชอัตโนมัติ

- ทุกครั้งที่เปิดหน้าเว็บ `js/boot.js` จะโหลดไฟล์ CSS/JS ของแอปพร้อม `?v=<เลข commit>-<วันที่และเวลาที่เปิด>`
  เช่น `js/app.js?v=3f2a9c1d4e5b-20260927-101530` จึงได้ไฟล์ล่าสุดเสมอ ไม่ใช้ไฟล์เก่าที่ค้างในแคช
- ไลบรารีขนาดใหญ่ใน `vendor/` (OpenCV, Tesseract, jsPDF, ฟอนต์) ใช้ `?v=<เลข commit>` — ได้ไฟล์ใหม่ทุกครั้งที่ deploy
  แต่ไม่ต้องดาวน์โหลดซ้ำหลาย MB ทุกครั้งที่เปิดหน้า
- ถ้าหน้า HTML เองค้างในแคชของเบราว์เซอร์/เครือข่าย ระบบตรวจ `version.json` แล้วโหลดหน้าใหม่ให้ 1 ครั้งอัตโนมัติ (ไม่วนซ้ำ)
- เลขเวอร์ชันและเวลาที่เปิดแสดงอยู่ท้ายหน้าแรก — เปิดไฟล์จากเครื่องหรือ repo โดยตรงจะแสดงเป็น "พัฒนา (dev)"

เนื่องจากเป็นไฟล์ static ทั้งหมด จึงวางบนโฮสต์ HTTPS อื่นได้เช่นกัน เช่น Netlify, Cloudflare Pages
หรือทดสอบในเครื่องด้วย `npx serve doc-scanner-pdf` แล้วเปิด `http://localhost:3000`

## ประสิทธิภาพ

- **Web Worker:** งานประมวลผลภาพทั้งหมดทำใน Web Worker หน้าจอและกล้องจึงไม่ค้างระหว่างประมวลผล
- **ประมวลผลขนานหลายหน้า:** เปิด worker ได้หลายตัวตามจำนวนแกน CPU และหน่วยความจำของเครื่อง (สูงสุด 4)
  ใช้ทั้งตอนสร้างภาพย่อและตอนสร้าง PDF (ประกอบหน้าเรียงตามลำดับเสมอ) และปิด worker ที่เปิดเพิ่มหลังสร้าง PDF เพื่อคืนหน่วยความจำ
- **WebAssembly SIMD:** เบราว์เซอร์ที่รองรับ (Chrome/Edge 91+, Safari 16.4+, Firefox 89+) ใช้ build แบบ SIMD ที่คำนวณหลายพิกเซลพร้อมกัน
  เบราว์เซอร์รุ่นเก่าสลับไปใช้ build พื้นฐานอัตโนมัติ
- **ไฟล์เล็กลงมาก:** build มีเฉพาะส่วน core + imgproc ที่แอปใช้จริง (ดาวน์โหลดแบบบีบอัด ~0.8 MB จากเดิม ~3.3 MB)
  และแยกไฟล์ `.wasm` เพื่อให้เบราว์เซอร์คอมไพล์ขณะดาวน์โหลดและเก็บผลคอมไพล์ไว้ใช้ซ้ำ (เปิดครั้งต่อไปเร็วขึ้น)

ผลวัดจริง (Chromium, จำลอง CPU ช้าลง 4 เท่า ≈ มือถือระดับกลาง, ภาพถ่ายเอกสาร 5 ภาพ):

| ขั้นตอน | เดิม (OpenCV บนหน้าเว็บ) | ใหม่ (Web Worker + SIMD) |
|---|---|---|
| โหลดตัวประมวลผลภาพพร้อมใช้ | 3.7 วินาที | 0.5 วินาที |
| เพิ่ม 5 หน้า (ตรวจจับขอบ + ภาพย่อ) | 8.9 วินาที (หน้าจอค้างนานสุด 1.6 วินาที) | 3.7 วินาที (ค้างนานสุด 0.3 วินาที) |
| สร้าง PDF 5 หน้า คุณภาพสูง | 27.4 วินาที (หน้าจอค้างนานสุด 6.9 วินาที) | 5.6 วินาที (ค้างนานสุด 1.5 วินาที) |

## ความปลอดภัยและความเป็นส่วนตัว

- **ไม่มีการส่งข้อมูลออก**: ภาพและ PDF ถูกสร้างในเครื่องผู้ใช้ทั้งหมด ไม่มี API หรือเซิร์ฟเวอร์ปลายทาง
- **Content-Security-Policy**: อนุญาตสคริปต์และ worker เฉพาะไฟล์จากเว็บไซต์นี้เท่านั้น (ไม่มีโดเมนภายนอก)
  ห้ามสคริปต์ inline, `object-src 'none'`, `base-uri 'none'`, `form-action 'none'`
  (ต้องเปิด `'unsafe-eval'` เพราะ OpenCV.js สร้างฟังก์ชันด้วย `new Function` ภายใน — ทดสอบแล้วว่าไม่มีจะใช้งานไม่ได้
  ทั้งนี้โค้ดของแอปไม่เคยส่งข้อความจากผู้ใช้ไปประมวลผลเป็นโค้ด)
- **ไฟล์ไลบรารีตรวจสอบได้**: ทุกไฟล์ใน `vendor/` มี `SHA256SUMS` — jsPDF ตรงกับไฟล์ใน npm release ทางการ
  และ OpenCV.js มี `BUILD-INFO.txt` บอกเวอร์ชันซอร์สและลิงก์ไปยัง workflow ที่สร้าง
- **Worker รับเฉพาะคำสั่งที่กำหนด** (detect / warp / process) โหลดสคริปต์ได้เฉพาะจากเว็บไซต์เดียวกัน
  และตรวจขนาดภาพ พิกัดกรอบ และค่าตั้งทุกครั้งก่อนประมวลผล
- **ป้องกัน XSS**: ข้อความจากผู้ใช้ (เช่น ชื่อไฟล์) แสดงผลด้วย `textContent` เท่านั้น ไม่ใช้ `innerHTML`
- **ชื่อไฟล์ PDF**: ตัดอักขระต้องห้าม, `../`, อักขระควบคุม และอักขระกลับทิศข้อความ (กันชื่อไฟล์หลอก)
- **ป้องกันไฟล์อันตราย/หน่วยความจำเต็ม**: ตรวจชนิดไฟล์, จำกัดขนาดไฟล์ 60 MB, จำกัดความละเอียด 120 ล้านพิกเซล
  (กัน decompression bomb), จำกัด 200 หน้า, คืนหน่วยความจำ OpenCV (WebAssembly) ทุกครั้งหลังใช้งาน
- **กล้อง**: ปิดกล้องทันทีเมื่อกดเสร็จ สลับแท็บ หรือออกจากหน้า
- **ตรวจเวอร์ชัน**: `version.json` ใช้เฉพาะเลข commit ที่เป็นเลขฐาน 16 เท่านั้น (ค่าอื่นไม่สนใจ) โหลดหน้าใหม่ได้ไม่เกิน 1 ครั้ง
  และถ้าไฟล์หาย/ช้าเกิน 3 วินาที แอปก็ทำงานต่อได้ตามปกติ
- **ข้อความใน PDF**: ตัดอักขระควบคุมและตรวจพิกัด/ขนาดทุกค่าก่อนเขียนลง PDF ข้อความถูกเข้ารหัสเป็นรหัสตัวอักษร (hex)
  จึงไม่มีอักขระพิเศษใดแทรกคำสั่ง PDF ได้
- **ไฟล์ PDF ที่นำมาแปลง**: ไม่รันสคริปต์/ฟอร์ม XFA, ตรวจว่าเป็น PDF จริง, จำกัดขนาดไฟล์/ภาพ/หน้า/canvas, ตัวอ่าน `/ActualText`
  อ่านเฉพาะข้อความและมีเพดานขนาด/จำนวน/ความลึกทุกขั้น ใช้ผลเฉพาะเมื่อโครงสร้างตรงกับ PDF.js ทุกตำแหน่ง, ไฟล์ Word/ZIP
  ที่สร้างผ่านการ escape XML และตรวจชื่อไฟล์ในไฟล์ ZIP (ห้าม `..`/พาธเต็ม)
- หากนำขึ้นโฮสต์ที่ตั้งค่า HTTP header ได้ แนะนำเพิ่ม `Content-Security-Policy: frame-ancestors 'none'`
  (ตั้งผ่าน `<meta>` ไม่ได้)
